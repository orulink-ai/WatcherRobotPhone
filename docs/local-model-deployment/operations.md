# 运维经验与复现边界

本文记录已验证的机器部署经验，不提供可直接操作任意机器的通用启动器。认证、路径、网络接口与进程配置保留在原实验机器；没有把机器专用绝对路径写入公共系统脚本。

## 1. Qwen 大权重加载

默认加载后一次性求值全部参数触发 Metal GPU Timeout；第二次改为惰性加载，再按参数树逐项求值，成功完成 BF16 全模型物化，耗时约47.4秒，峰值333.2GiB。

这是实际修复结果，不是对所有架构适用的保证；未做多轮冷启动压力测试。模型权重保持单份，没有另存完整 BF16 转换副本。下载残留也未自动删除。

## 2. DS 双机与缓存

双机先验证严格 JACCL 的 CPU/GPU all-sum，再进行完整模型测试；两节点输出一致性、取消恢复、上下文及重启单独验证。使用官方 native FP4/FP8，未离线全量转换，初期无MTP。

文本前缀缓存需要适配模型的压缩注意力和 Engram 状态，不能直接把普通 KV 裁剪策略套用。验证配置使用同步前缀检查点与 LRU，最多8项、每rank4GiB。固定工具前缀和会话末尾检查点减少重复预填充。

曾测试 prefill=2048 优于512的固定用例，但新长任务触发GPU超时后已回退512。稳定性结论优先于特定样本吞吐。

## 3. 安全切换与两层保活

- 先停止接收新请求并等待当前请求结束，再退出工作进程、确认端口和模型资源释放，最后启动另一巨型模型。
- DS/Qwen共享实验API端口，health必须校验真实模型名与ranks，不能只检查HTTP 200。
- 唯一实例、生命周期锁、启动宽限、失败阈值及恢复冷却用于避免重复加载。
- 快照时DS的launchd守护启用、每20秒检查；Qwen守护禁用，暂停/维护标志保留。
- 聊天定时巡检与launchd独立。暂停聊天任务不等于关掉系统守护；仅杀模型进程可能被重新拉起。
- 双机使用临时RDMA IPv4配置及现有雷雳SSH路径，系统重启后应核验网络、权限、防睡眠和服务顺序；不能承诺无人工恢复。

## 4. 正确区分测试输入

StartLux Instant使用专用双向注意力和决策概率读出，普通多模态生成不能代替官方决策路径验证。控件树纯文字评测没有图片输入；报告中的截图可仅作人工审计。

Qwen/UI-Venus的归一化坐标必须按图片宽高映射为像素；模型的代码围栏、嵌套数组和对象应解析并校验后才交给执行器，不能直接执行任意模型文本。
