## Qwen 单机 BF16

M3 Ultra / 512GiB；固定官方权重与隔离环境版本见[清单](inventory.md)。惰性加载逐参数求值47.365秒，峰值333.168GiB；测试前后交换空间约18.69MiB。温度0、关闭思考、输出上限256 tokens。

## DS 双机和 Pi

完整模型初始验证包含53项功能检查、55对rank输出一致，图文、多轮、SSE、取消恢复、7387 token检索和重启。初期长文解码中位17.15 token/s，每rank峰值约149.15GiB。

相同Pi代码任务三轮中位：优化前35.11秒，精简提示/工具及同步前缀缓存后12.76秒，约2.75倍。它主要省去了重复预填充，不是逐token解码快了2.75倍。17K工具前缀的冷请求仍约50秒，热复用可明显下降。

Qwen后来另行完成API、工具协议与Pi读改测：历史报告记录433项项目测试、7项网关、3项工具协议、11项API smoke、10项扩展检查和3项长工具用例通过。它们是历史执行记录，本次仅归档，不宣称在黑客松main重新跑过这些代码。

## 历史手机完整任务

此前Pi + Android MCP的小红书固定流程，各3轮，官方DS平均27.77秒、本地DS双机69.30秒，约2.50倍；6轮均成功并恢复点赞/收藏状态。

该结果沿用当时真实手机、USB/MCP、候选控件与验证器，不是本轮重跑，也不是Qwen或ESP32 HID的真机结果。硬件、网络、API版本、缓存和任务约束均影响耗时。

## 对项目的意义

官方DS可作为低等待时间的对照基线；本地Qwen证明了离线图文和单步动作生成的可用性；DS提供双机本地Agent/API路径；StartLux则提供低生成开销的候选决策路线。最终后端选择仍需同一Application/设备执行链路上的多轮质量、失败恢复与长期稳定性验证，不能只按token/s排名。
