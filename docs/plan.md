# 48 小时计划与验收

以下使用相对时间，不将仓库初始化时间当作比赛正式开始时间。进度仅在拿到实测证据后更新。

| 阶段 | 工作 | 交付与验收 |
| --- | --- | --- |
| H0–H6 | 确定手机平台；验证整屏采集、权限、后台存活与 BLE HID | 留存系统版本、设备型号和跨 App 新帧证据；能手动控制大按钮 |
| H6–H14 | 指针校准、归零、点击、释放及状态回执 | 固定竖屏与速度；记录目标点、实际误差；断开后不继续发送旧动作 |
| H14–H26 | 模型单步决策与图像变化检查 | 任务与截图产生合法动作；旧画面动作被丢弃；执行后重新观察 |
| H26–H36 | SDK Application 接入机器人语音与 Device channel | 任务进入 Application；业务动作经 Daemon 到设备；无内容级路由旁路 |
| H36–H44 | 固定演示场景，连续复测与异常恢复 | 记录至少 5 次运行的实际成功数、步骤与耗时；失败原因可追踪 |
| H44–H48 | 录制演示、整理照片与说明、准备评审 | README 指向真实运行结果；录屏、测试表和限制说明齐备 |

## MVP 验收清单

- [ ] 用户能提交任务，Application 能展示当前状态。
- [ ] 能持续得到目标 App 的新屏幕，图像附带尺寸、时间与流标识。
- [ ] 模型每轮只返回一个经过校验的动作。
- [ ] 模型坐标通过校准变成相对 HID 位移。
- [ ] ESP32 能完成移动、点击、释放，并返回可匹配的序号与状态。
- [ ] 动作后重新观察；板端回执不直接当作业务成功。
- [ ] 页面突变、屏幕停止共享、断连或无效回复时停止旧动作。
- [ ] 支持暂停、停止与人工接管。
- [ ] 固定演示任务跑通，公布实际成功率与耗时。

## 实现前先关闭的不确定性

1. 平台：参考项目依赖 iOS 27 / Xcode 27；目标手机是否满足、是否采用 Android 替代方案，先实测再决定。
2. HID：手机系统对配件输入的行为、AssistiveTouch 或对应系统设置、指针加速度与校准误差。
3. 固件共存：现有机器人 BLE 配网服务与 HID 的连接预算、配对安全、服务生命周期与内存。
4. Application：手机图像接入接口、任务会话及设备动作协议尚需定义。

## 测试驱动与证据

业务实现先定义动作校验、坐标转换、回执关联和旧画面拒绝等可测试行为，再实现功能。真机相关能力用实际步骤、输入输出与录屏验证，不以静态测试代替硬件测试。尚未运行的项目不填写通过。
